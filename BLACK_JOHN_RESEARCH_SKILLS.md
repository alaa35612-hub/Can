# Black John Research Skills Registry

## Purpose
This package turns Black John knowledge into a disciplined, criticizable research corpus. It does not modify production code and does not treat legacy rules as facts.

## Mandatory load order for research tasks
1. `.claude/skills/black-john-research-governance/SKILL.md`
2. `.claude/skills/black-john-fact-reconstruction/SKILL.md`
3. `.claude/skills/black-john-research-state-ledger/SKILL.md`
4. `.claude/skills/black-john-hypothesis-engine/SKILL.md`
5. `.claude/skills/black-john-background-corpus/SKILL.md`
6. `.claude/skills/black-john-previous-analysis-auditor/SKILL.md`
7. `.claude/skills/black-john-blind-replay/SKILL.md`
8. `.claude/skills/black-john-rule-validation-lifecycle/SKILL.md`
9. `.claude/skills/black-john-cross-coin-synthesis/SKILL.md`
10. `.claude/skills/black-john-current-scan-research/SKILL.md`

Load existing specialist skills such as structural-state-ledger, structural-pattern-detector, adaptive-feature-engineer, OI positioning, explainability and causal backtesting only as supporting domain references. The governance skill remains authoritative.

## Authority principle

```text
Research protocol governs.
Raw data judges.
State Ledgers preserve context.
Skills propose hypotheses.
Blind replay tests detectability.
Controls prevent sample illusion.
Previous analyses are audited.
```

## Research workflow

```text
Inventory and quality audit
→ chronological fact reconstruction
→ campaign segmentation
→ persistent State Ledger update
→ competing hypotheses
→ adversarial review
→ successful/failed/control comparison
→ blind replay
→ rule status decision
→ cross-coin synthesis
→ research-grounded current scan
```

## Rule statuses
- BACKGROUND_CONCEPT
- RESEARCH_HYPOTHESIS
- SUPPORTED_PATTERN
- CONDITIONAL_RULE
- DURABLE_RULE
- REJECTED_RULE
- DEPRECATED

## Legacy Black John v21 treatment
Black John v21 is a valuable background source for chronological reading, causal Price/OI/L/S/Trades/Acceptance questions, cumulative context, separation of signal importance from entry safety, and candidate validation ideas. Its OKX/Top-Gainers/15m-derived claims and numeric thresholds must be marked as limited validation and re-tested on project Binance data, failed cases, controls and blind replay.

## Scope of this installation
Documentation and agent-research skills only. No scanner, engine, backtest or production-code behavior is changed.
