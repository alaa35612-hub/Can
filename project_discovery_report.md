## 2. Python version selection

- `2_v321_operational_v321o_patch1.py` is the latest/primary operational engine: README names it as the base file and it contains the V3.2.1-O decision tree, runtime scanner, audit, and self-test.
- `backtest_v321o_uploaded_cases.py` is the existing uploaded-case harness; it is useful as baseline reference but not a full project discovery harness.
- Therefore the new production candidate should be derived conservatively from `2_v321_operational_v321o_patch1.py`, not from an older report artifact.

## 3. Methodology extracted from the project

- The project is built around a structural futures scanner: Data Quality -> Dynamic Baseline -> Phase Memory -> OI / Quote validation -> Price State -> OI State -> L/S structure -> Trades regime -> Base/Reset/Trigger/Acceptance -> Conflict Resolution -> Readiness/Confidence.
- RSI is contextual only and must not drive classification.
- Quote Volume is frequently absent in the uploaded tables; the documents and README require no automatic rejection when it is missing. Missing quote volume should cap confidence rather than invalidate a setup.
- A valid backtest must run candle-by-candle with only past/current candles visible to the classifier. Future windows are allowed only after classification for evaluation labels.
- Existing baseline reports show all 16 parsed symbols are rising cases, so precision cannot be claimed reliably without non-rising controls.

## 6. Patterns that repeatedly preceded the rise

1. **Base or compression before expansion**: most starts had a measurable range/base in the prior 8 candles. The median base range was about 5.1%; very tight examples existed (DYDX/CLO), and wider meme/pump bases existed (GUA/TST/EDEN).
2. **OI build is useful but not mandatory**: median 24-bar OI change was positive (~4.7%), but several valid rises had flat/down OI before the move (CLO, DYDX, OPN, UB, JTO). Rules that require OI expansion before price will miss price-led and squeeze/vacuum cases.
3. **Late or delayed OI confirmation**: many cases start with price/base acceptance first, then OI catches up on/after the trigger. This supports a delayed-OI recognition path rather than rejecting flat OI.
4. **Trades expansion helps but is not universal**: median trades ratio was ~1.36x; strong winners often had clear activity (DOGS, TST, MAGMA, EDEN), but GUA started with low immediate trades relative to its previous burst. Trades should be a support/confirmation feature, not a single hard gate.
5. **L/S divergence matters most when Top Positions retain long exposure while accounts/global are less enthusiastic**: the median position-account spread was positive; BSB, NIL, BEAT and UB show stronger top-position retention than top-account/global crowding.
6. **Reset/flush is valuable when present, but absence is acceptable**: roughly half the selected major starts had a recent reset/flush. Strict reset requirements would miss clean continuation bases.
7. **Quote Volume is unavailable in the uploaded data**: all parsed uploaded candle tables lack real quote volume, so quote-volume disagreement cannot be used as a reliable false-positive filter here.

## 7. Patterns that appear after it is too late

- Large OI shock after price already expanded: useful for confirmation, but often late for early discovery.
- Acceptance only after a large candle and high RSI: confirms live strength but reduces lead time.
- High trades only at the peak candle: often describes crowd participation rather than pre-rally accumulation.
- Conflict cleanup that waits for all L/S layers to align: by then account/global can already be chasing.

## 8. Patterns that fail or become false/low-quality signals

- OI rise while price is not in a stable base and top positions do not retain direction: likely leverage noise.
- Trades expansion without price acceptance or base high reclaim: can be churn/noise.
- Crowded long accounts/global without position-account quality spread: may be late chasing, not institutional accumulation.
- Missing quote volume interpreted as bad quote-volume validation: this is data-quality noise, not market evidence.
- Price move already far above base with negative lead bars: backtest classifies it as late even if the structural label is bullish.

## 10. Gaps between current code and actual data

- Existing baseline detects only 3/16 rising events as early/live and marks 13/16 as late due to trigger timing. Baseline summaries: early_watch recall 18.75%, strict_live recall 18.75%.
- Current rules are too dependent on fully confirmed trigger/acceptance and not enough on pre-trigger base + structural pressure.
- Flat/down OI price-led cases need a first-class pattern instead of being downgraded into unclear/mixed until after the move.
- Missing quote volume must not drive micro-noise rejection; all uploaded data is missing quote volume.
- Candidate timelines need richer per-candle diagnostics explaining which exact conditions blocked discovery.
- Backtest labeling should distinguish first useful signal, live-at-start signal, late signal, and signals too early whose future return is exhausted before the event.
